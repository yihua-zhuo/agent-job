## 1. 目标与背景

### 1.1 为什么做

The campaign and event domain currently has no dedicated service layer. Upstream routers must write raw SQL or bypass established service conventions, creating inconsistent error handling and tenant-scoped queries. Issue #759 is a prerequisite for any campaign-facing feature (email automation, trigger-based notifications, event tracking).

### 1.2 做完后

- **用户视角**：No user-visible change — this is a pure backend infrastructure addition.
- **开发者视角**：`MarketingService` exposes 10 typed, tenant-isolated methods. Routers can delegate `create_campaign`, `get_campaign`, `update_campaign`, `launch_campaign`, `pause_campaign`, `get_campaign_stats`, `list_campaigns`, `record_event`, `get_user_events`, and `setup_trigger` to the service instead of writing raw SQL. ORM models `Campaign` and `CampaignEvent` are registered in Alembic for migration support.

### 1.3 不做什么（剔除）

- [ ] No API router for marketing endpoints — that is a separate issue.
- [ ] No email / notification sending implementation — only trigger setup (storing trigger config).
- [ ] No auth middleware changes — auth context from `require_auth` is assumed to be already available.
- [ ] No migration execution in this board — generate the migration file only.

## 4. 设计决策与已知坑

### 4.1 关键选型

- **JSONB columns for config/event_metadata/payload** instead of nullable TEXT: gives DB-level query capability on JSON fields (e.g. `WHERE event_metadata->>'type' = 'click'`) and avoids application-level JSON parsing overhead.
- **Separate `CampaignEvent` table** instead of embedding events as a JSONB array on `Campaign`: avoids row-level write contention and large row sizes; each event is independently queryable.
- **`event_metadata` / `payload` column names** instead of `metadata`: SQLAlchemy `Base.metadata` (the `MetaData` object) collides with any column named `metadata` on a Base subclass at class definition time.

### 4.2 版本约束

<!-- 没有新依赖时整段删掉。如有，按下表填：-->

| 依赖 | 版本 | 理由 |
|------|------|------|
| TBD | TBD | No new external dependencies; all packages already present in pyproject.toml |

### 4.3 兼容性约束

- `MarketingService.__init__(self, session: AsyncSession)` — `session` has NO default; caller must provide it.
- Every SQL query filters by `tenant_id` in the WHERE clause.
- Service methods return ORM objects (e.g. `Campaign` instance) — do NOT call `.to_dict()` in the service.
- Service raises `AppException` subclasses (`NotFoundException` when campaign not found, `ValidationException` for invalid status transitions) — do NOT return `ApiResponse`.
- Router handles `.to_dict()` serialization and response envelope wrapping.
- Imports use `from db.models.campaign import Campaign` (PYTHONPATH=src), NOT `from src.db.models.campaign`.

### 4.4 已知坑

1. **Alembic autogenerate emits `sa.JSON()` for JSONB columns** → after autogenerate, manually change `sa.JSON()` to `sa.JSONB()` in the migration; otherwise `WHERE` operators on JSON keys will be slow.
2. **Alembic autogenerate drops `timezone=True` on DateTime columns** → verify `server_default=func.now()` or `server_default=text('now()')` has timezone-aware variant; PostgreSQL `TIMESTAMPTZ` is preferred.
3. **`Base.metadata` collision** → column on ORM model must be named `event_metadata` or `payload`, never `metadata`.
4. **`alembic/env.py` must import all ORM models** → if `Campaign` or `CampaignEvent` is not imported in `env.py`, autogenerate silently skips the table.
